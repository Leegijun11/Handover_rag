# 0. 이 문서를 어떻게 쓰나

이 문서는 참고용 기획서가 아니라, **바이브코딩(Claude Code)에 그대로 입력할 스펙**입니다. 3명 모두 Claude Code를 사용하므로, 각자 담당 모듈에 해당하는 부분(3번 데이터 모델, 4번 API, 6번 기술 스택, 7번 폴더 구조)을 그대로 복사해서 Claude Code에 넣고 작업을 시작하세요.

## 엄격하게 고정하는 것 (임의 변경 금지)

- 공통 데이터 모델(3번) — 필드명, 타입
- API 명세(4번) — 엔드포인트, 요청/응답 형식
- 기술 스택(6번)
- 폴더 구조(7번)

이 네 가지는 조장이 사전에 확정한 스펙이며, 팀원은 이 범위 안에서 자유롭게 구현하면 됩니다. 함수명·내부 로직·구현 방식은 담당자 재량이며, 연결되는 다른 모듈 담당자와만 그때그때 맞추면 충분합니다 (별도 승인 불필요).

## 느슨하게 가는 부분

- 위 네 가지를 뺀 세부 구현은 각자 판단대로 진행
- 모듈 간 함수명·내부 구조는 인접 담당자끼리 직접 협의

## 문서 변경 권한

이 문서(스키마·API·스택·폴더구조 포함)의 수정 권한은 조장에게만 있습니다. 작업 중 변경이 필요하다고 판단되면, 팀원은 직접 고치지 말고 조장에게 요청하세요.

## 개발 방식 (2단계)

1. **1차 빌드**: 이 문서의 초안 스펙 그대로 3명이 각자 모듈을 구현해 전체 앱을 한 번 완성
2. **피드백 반영**: 각자 사용해보며 발견한 문제점을 모아 조장이 스펙을 수정 → 필요한 부분만 재작업

즉 지금 단계의 스펙은 "완벽한 최종안"이 아니라 **1차 빌드를 위한 기준선**입니다. 처음부터 완벽하게 맞추려 하기보다, 이 기준으로 일단 끝까지 만들어보고 나서 다듬는 걸 목표로 하세요.
