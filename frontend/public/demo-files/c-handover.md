# 배포

운영 배포는 화요일과 목요일 오후 2시에만 한다. 금요일과 공휴일 전날에는 배포하지 않는다.
배포는 혼자 하지 않고, 배포 채널에 롤백 담당자를 먼저 정한 뒤 시작한다.

## 운영 배포 절차

배포할 PR은 main에 머지되고 스테이징에서 30분 이상 문제가 없어야 한다.

배포는 CI의 'deploy-prod' 워크플로를 수동 실행해서 시작한다. 실행 전에 배포 채널에 대상 PR 목록과 롤백 담당자를 적는다.

배포 후 15분 동안 에러율 대시보드를 지켜보고, 이상이 없으면 채널에 완료를 남긴다.

## 롤백

배포 후 에러율이 평소의 2배를 넘으면 원인을 찾기 전에 먼저 롤백한다.

롤백은 'deploy-prod' 워크플로를 직전 태그로 다시 실행하면 된다. DB 마이그레이션이 포함된 배포는 코드만 되돌리면 안 되므로 반드시 사수에게 먼저 알린다.

# 온콜

온콜은 주 단위로 돌아가며, 첫 한 달은 사수와 함께 2인 1조로 선다.

## 장애 대응

알림이 오면 5분 안에 장애 채널에 '확인 중'을 남긴다. 사용자 영향이 있으면 등급을 SEV2 이상으로 올린다.

원인을 모르는 상태에서는 최근 배포부터 의심하고, 30분 안에 해결되지 않으면 사수를 호출한다.

장애가 끝나면 48시간 안에 회고 문서를 쓴다.

## 알림 기준

API p95 응답 시간이 1초를 넘거나 5xx 비율이 1%를 넘으면 알림이 온다. 야간(23시~8시)에는 SEV2 이상만 전화로 호출된다.

# 개발 환경

로컬 개발 환경과 권한은 입사 첫 주에 모두 준비한다.

## 로컬 개발 환경

로컬 개발은 docker compose로 DB와 캐시를 띄운다. 시드 데이터는 'make seed'로 넣고, 운영 데이터는 절대 로컬로 내려받지 않는다.

## 권한 신청

저장소 쓰기 권한은 입사 당일, 스테이징 접근은 첫 주에 받는다. 운영 DB 조회 권한은 입사 한 달 뒤에 신청할 수 있다.
